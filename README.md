# 检查数据统计工作台（Checkup Workbench）

面向医院数据管理员的本地智能工作台：批量导入检查报告（PDF/扫描件）→ 本地智能识别 → 人工校对 → 统一归档统计 → 单患者指标趋势图 → Excel 导出。

> **隐私承诺**：服务只绑定 `127.0.0.1`，OCR 使用 RapidOCR 在**本机离线推理**（首次运行需联网下载一次模型到本机缓存），SQLite、源文件、识别缓存全部保存在 `backend\data`，**不依赖任何外部网络服务**。

## 功能一览

| 页面 | 说明 |
|---|---|
| 工作台概览 | 患者/报告/待校对/异常指标统计卡 + 最近导入批次与近期异常提醒 |
| 批量导入中心 | 一次拖入多个 PDF / 图片；自动判别电子版 PDF（抽文本）与扫描页（本地 OCR）；任务级进度展示、失败重试 |
| 报告编辑（患者库内） | 左“报告原文/页面图”右“结构化结果”：改患者/日期/类型/医院，增删检验行，换模板重解析；识别不达标的报告在患者库顶部“待核对”中处理 |
| 患者库 | 患者档案归集（同名检测与合并）、报告时间线、每份报告检验明细 |
| 趋势分析 | 选择患者 + 检验项目，ECharts 展示历次数值曲线，标注参考范围与高/低异常点，可导出该指标序列 Excel |
| 模板与导出 | 解析模板列表/新建/编辑（表格式列规则 + 患者信息正则 + 匹配词），支持“上传样例实时调试”；数据导出中心一键导出 .xlsx |

## 两种使用方式

| 方式 | 适用对象 | 目标机是否需要安装环境 |
|---|---|---|
| **绿色免安装版**（推荐给使用方） | 把 `dist\检查数据统计-绿色版` 文件夹拷到任意电脑 / U 盘 | **不需要** Python、Node.js，也不需要联网 |
| 源码运行（开发调试） | 在本仓库中开发与调试 | 需要 Python 3.11/3.12 与 Node.js 18+ |

### 方式一：绿色免安装版（双击即用）

双击 `dist\检查数据统计-绿色版\start.bat`，几秒后自动打开浏览器。

- `runtime\python`：内嵌运行环境（Python 3.12 + 全部依赖）；
- `web`：已构建好的前端页面；
- `backend\data`：数据库与上传文件（备份 / 迁移只需复制它）；
- OCR 模型已内置，**全程无需联网**。

详细说明见文件夹内的 `使用说明.txt`。
需要重新制作时，在本仓库双击 **`build_portable.bat`**（需联网下载约 100MB），产物输出到 `dist\检查数据统计-绿色版`。

### 方式二：源码运行

环境要求：Windows 10/11 + Python **3.11 / 3.12**（勾选 *Add python.exe to PATH*）+ Node.js 18+（仅首次构建前端需要）。

双击 **`start.bat`**：

1. 首次运行自动创建 `backend\.venv` 虚拟环境并安装后端依赖；
2. 首次运行自动 `npm install` 并构建前端页面（约 10–30 秒）；
3. 自动启动本地服务并打开浏览器（默认 `http://127.0.0.1:8321`，端口被占用时自动顺延到 8322…）。

关闭黑色控制台窗口即停止服务；数据不会丢失。

## 手动启动

```bat
:: 1. 后端虚拟环境（首次）
py -3 -m venv backend\.venv
backend\.venv\Scripts\pip install -r requirements.txt

:: 2. 前端构建（首次 / 修改前端后）
cd frontend
npm install
npm run build
cd ..

:: 3. 启动服务
cd backend
.venv\Scripts\python -X utf8 -m uvicorn app.main:app --host 127.0.0.1 --port 8321
```

浏览器打开 http://127.0.0.1:8321 ；接口文档见 http://127.0.0.1:8321/api/docs 。

## 使用流程

1. **批量导入** → 到“批量导入中心”拖入报告；识别达标（姓名、日期齐全且有检验项）的报告**自动入库**，不达标的进入患者库顶部“待核对”；
2. **核对 / 修改** → 待核对项点“去核对”，已入库报告点右侧 ✏️，两者打开同一个编辑器：对照报告图像修改患者信息与检验行后保存；识别不准时也可点 ⟳“重新解析”用最新规则重识别；
3. **统计与趋势** → 入库数据在“患者库 / 趋势分析”中即时可用；单指标历次曲线带参考范围带与异常着色；
4. **模板调校** → 版式不匹配时，到“模板与导出”中新建/修改模板（表头列别名、正则、匹配词），并用样例文件实时调试命中效果；
5. **导出 Excel** → “数据导出中心”按患者/报告类型筛选导出全部明细，或到“趋势分析”页导出单个指标序列。

## 数据与备份

- 全部数据在 `backend\data`：`app.db`（SQLite 数据库）、`uploads\`（源文件）、`page_images\`（OCR 页图缓存）、`ocr_cache\`（识别文本缓存）、`templates\`（界面自定义的模板）。
- 备份：关闭服务后复制整个 `backend\data` 文件夹即可；迁移到新机器同理。
- 清空数据：停止服务后删除 `backend\data\app.db` 并重启即可（保留上传与 OCR 缓存可加速重复导入）。

## 常见问题

- **首次导入提示“OCR 引擎初始化”**：RapidOCR 首次需要从模型仓库下载约 15–50MB 的检测/识别模型到本机缓存（`%USERPROFILE%\.cache\rapidocr`），此后完全离线。下载失败请检查网络后重试导入。
- **识别不准 / 版式不匹配**：请到“模板与导出”页使用“上传样例调试”定位问题：补充表头列别名、姓名/日期正则或调整匹配关键词，保存后用“重新解析”观察效果。
- **端口被占用**：若 8321 被占用，请先关闭占用进程；如需改端口，同时修改 `backend\app\config.py` 的 `PORT` 与 `frontend\vite.config.ts` 中的代理目标。

## 开发

- 后端测试：`backend\.venv\Scripts\python tests\e2e_api.py`
- 前端开发模式：`frontend` 下 `npm run dev`（Vite 已代理 `/api` → `127.0.0.1:8321`）
